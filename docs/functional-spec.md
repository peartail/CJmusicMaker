# MusicBitMaker 기능 명세

기준일: 2026-10-24 · 기준 소스 버전: v0.1036 · 대상: Windows x64 네이티브 앱

이 문서는 현재 제품 동작, 기대 동작, 검증 상태를 구분하는 기준이다. `src/Main.cpp`, `README.md`와 현재 작업 폴더의 구현을 기준으로 작성했다. “구현”은 코드 경로가 존재한다는 뜻이며, 모든 사용자 시나리오가 정상 검증되었다는 뜻은 아니다. 특히 악기 음색 변경은 사용자 보고에 따라 미해결 문제로 관리한다.

## 1. 제품 범위와 용어

개인용 음악 제작 앱으로, 건반과 드럼 연주를 MIDI로 녹음하고 트랙별로 편집·믹싱한 뒤 프로젝트로 저장한다. 최종 목표에는 오디오 가져오기와 WAV 출력도 포함되지만 현재 사용자 기능으로 제공되지 않는다.

| 용어 | 의미 |
| --- | --- |
| 프로젝트 | 트랙, MIDI, 악기, 믹서, 재생 상태 등을 담는 Tracktion Edit |
| 트랙 | 악기 하나와 해당 MIDI 패턴을 배치하는 단위 |
| 악기(Instrument) | 트랙에서 MIDI를 실제 소리로 바꾸는 신시사이저 또는 드럼 프리셋 |
| 음높이 | C4, D4처럼 연주하는 음. MIDI 노트 번호로 저장 |
| 음색 | 같은 C4를 연주해도 악기에 따라 달라지는 소리의 성격 |
| Root / Scale | 기준음 / 음계. 현재는 건반 색상 안내에 사용 |
| Octave | 건반 입력의 음역. 한 단계 이동하면 MIDI 음높이가 12만큼 변경 |
| Loop / Cycle | 정한 시작점과 끝점 사이를 되돌아가며 반복 재생하는 기능 |
| Loop Range | 모든 트랙에 공통으로 적용되는 반복 재생 시작·끝 구간 |

프로젝트의 음악 상태는 Tracktion Edit를 기준으로 한다. UI는 상태를 표시하고 변경하는 역할을 한다. C# WinForms 프로젝트는 과거 프로토타입이며 이 문서의 기능 대상은 C++ 앱이다.

## 2. 기본 작업 흐름

1. 새 프로젝트를 만들거나 `.tracktionedit` 파일을 연다.
2. `+ ADD TRACK`에서 악기를 선택해 트랙을 추가한다.
3. 트랙을 선택하고 건반 또는 드럼을 연주해 소리를 확인한다.
4. `RECORD`로 녹음을 시작하고 입력한다. 재생 중 다른 트랙을 선택해 레이어를 추가할 수 있다.
5. 녹음을 종료하고 타임라인에서 노트 시간·음높이·길이를 편집한다.
6. 트랙별 Volume, Pan, Mute, Solo를 조절한다.
7. 프로젝트를 저장하고 다시 열어 동일한 패턴과 악기 설정이 복원되는지 확인한다.

### 3.1 건반 및 단축키

| 입력 위치 | 조작 | 동작 |
| --- | --- | --- |
| 건반·메인 창 | A W S E D F T G Y H U J | 기본 배치에서 가운데 옥타브 C~B. Edit → Shortcuts에서 변경 가능 |
| 건반·메인 창 | 사용자 지정 키 | 왼쪽·가운데·오른쪽 36음을 각각 지정하거나 해제 |
| 건반·메인 창 | N / M | 기본 배치에서 한 옥타브 내림 / 올림. 변경 가능 |
| 건반 창 | Octave / Root / Scale | 왼쪽부터 옥타브, 기준음, 음계 선택 |
| 메인 창 | Z / X / C / V | Kick / Snare / Closed Hat / Open Hat |
| 건반·메인 창 | Space | 기본 Play / Stop 토글. Edit → Shortcuts에서 변경 가능 |
| 건반·메인 창 | 사용자 지정 키 | Loop 켜기 / 끄기. 기본값은 미지정 |
| 메인 창 | Ctrl+N / Ctrl+O | 새 프로젝트 / 열기 |
| 메인 창 | Ctrl+S / Ctrl+Shift+S | 저장 / 다른 이름으로 저장 |
| 메인 창 | Delete / Backspace | 선택 노트 삭제 |

연주·재생 단축키는 모든 프로젝트에 공통인 사용자 설정이며 프로젝트 파일에는 저장하지 않는다. 피아노 단축키는 12개 Root와 Major/Natural Minor 조합별로 저장되어 건반 창의 Root/Scale 변경과 함께 전환된다. 드럼, 옥타브 이동, Play/Stop, Loop 키는 모든 음계 프로필에서 공통이다. 한 키는 현재 프로필 안에서 한 동작에만 지정할 수 있고, 설정 창이 키 입력을 기다리는 동안에는 악기가 연주되지 않는다. Play/Stop과 Loop는 메인 창 및 분리된 건반 창에서 동작하며, 현재 파일·편집 단축키는 메인 창 전용이다.

### 3.2 건반의 음계와 옥타브

- 화면 건반은 시작 옥타브부터 3옥타브(36음)를 표시하고 모든 음을 마우스로 연주할 수 있다. 새 프로젝트 기본 Octave 3의 범위는 C3~B5이고, 가운데 C4~B4에 A/W/S/E/D/F/T/G/Y/H/U/J가 연결된다. 좌우 옥타브는 기본 미지정이며 Edit → Shortcuts에서 지정한다. 시작 옥타브 0~6의 전체 선택 범위는 C0~B2부터 C6~B8까지다.
- 옥타브 변경은 건반의 음 이름, 이후 실제 입력과 녹음 음높이를 함께 변경한다. 이미 녹음된 노트는 이조하지 않는다.
- 옥타브 전환 시 기존에 누른 음을 먼저 종료해 이전 음이 남지 않도록 한다.
- Root와 Scale은 음색·음높이를 자동 변경하거나 음계 밖의 입력을 차단하지 않는다.
- Root, Scale, Octave는 프로젝트 공통 설정이며 트랙별 설정이 아니다. 새 프로젝트는 C / Major / Octave 3을 사용하고, 저장된 Octave가 없는 옛 프로젝트는 이전 기본값 4를 유지한다.

### 3.3 악기 목록과 의도

현재 악기는 외부 샘플이 아닌 Tracktion FourOsc로 합성한다. 아래 소리 설명은 프리셋의 의도이며, 실제 청감이 모두 검증되었다는 뜻은 아니다.

| 종류 | 이름 | 의도 |
| --- | --- | --- |
| Synth | Generated Keys | 기본 건반 음색 |
| Synth | Retro Pulse | 짧고 또렷한 펄스 계열 |
| Synth | 8-Bit Lead | 사각파 중심의 레트로 리드 |
| Synth | Space Beep | 딜레이·리버브가 있는 전자음 |
| Synth | Cosmic Pad | 느린 어택과 긴 릴리스의 배경 음색 |
| Drum | Kick | 킥, MIDI 36 |
| Drum | Snare | 스네어, MIDI 38 |
| Drum | Closed Hat | 짧은 하이햇, MIDI 42 |
| Drum | Open Hat | 긴 하이햇, MIDI 46 |

합성 원리와 프리셋 파라미터 설명은 [신시사이저 기초](synthesis-basics.md)를 참고한다.

## 4. 악기 변경의 기대 동작과 인수 기준

악기 변경 성공은 메뉴 이름이나 상태 메시지가 바뀌는 것만으로 판정하지 않는다. 새로 연주하는 소리와 기존 MIDI 재생 소리에 새 음색이 적용되어야 한다. 신시사이저끼리 변경할 때 MIDI 음높이는 유지되고 음색이 변경되는 것이 정상이다.

| ID | 변경 상황 | 기대 동작 / 통과 기준 |
| --- | --- | --- |
| INST-AC01 | Synth → 다른 Synth | 노트의 음높이·시작·길이를 유지하고, 같은 음을 연주·재생하면 새 음색 출력 |
| INST-AC02 | Drum → 다른 Drum | 타이밍·길이를 유지하고 노트 번호를 새 드럼 번호로 변경. 실제 출력도 새 드럼 소리 |
| INST-AC03 | Synth ↔ Drum | 노트 초기화 경고 표시. 취소하면 유지. 승인 시 해당 트랙의 MIDI 노트를 초기화하고 입력 창 활성 상태 갱신 |
| INST-AC04 | 재생 중 변경 | 이후 출력에 새 악기 적용. 이전 악기의 소리가 계속 남거나 중복 발음하지 않음. 재생 위치를 의도치 않게 초기화하지 않음 |
| INST-AC05 | 음을 누른 상태에서 변경 | 기존 Note Off를 정리하고 이후 입력은 새 악기로 출력. 키를 놓은 후 지속되는 비정상 발음 없음 |
| INST-AC06 | 연속 변경 A → B → A | 이전 프리셋의 이펙트·파형·엔벌로프 값이 섞이지 않고 각각 원래 소리로 복귀 |
| INST-AC07 | 저장 후 재실행·불러오기 | 악기 이름, 실제 음색, MIDI와 믹서 값이 저장 시점과 일치 |
| INST-AC08 | 다른 트랙 존재 | 대상 트랙만 악기 변경. 다른 트랙의 악기·노트·믹서 유지 |
| INST-AC09 | 같은 악기 선택 / 취소 | 트랙과 MIDI에 변경 없음 |
| INST-AC10 | 적용 실패 | 실패 메시지 표시. 부분 적용 여부를 확인하며 성공으로 표시하지 않음 |

위 기준은 정상 동작의 목표다. 현재 구현이 모든 기준을 만족한다는 보장은 없으며, 아래 문제 해결 시 검증 항목으로 사용한다. 악기 변경만으로 트랙 이름을 자동 변경해야 한다는 요구사항은 현재 확정하지 않는다.

## 5. 알려진 문제와 확인 과제

### BUG-001: 악기 변경 후 실제 소리가 제대로 바뀌지 않음

- 상태: 사용자 보고, 미해결. 우선 확인 대상.
- 보고 내용: Instrument를 바꾸어도 소리가 기대한 대로 바뀌지 않음.
- 아직 확인하지 못한 내용: 특정 프리셋 조합인지, 직접 건반 연주와 기존 MIDI 재생 모두 발생하는지, 재생 중에만 발생하는지, 재실행·불러오기 후에도 동일한지.
- 영향: 악기 선택·변경 기능을 청감상 정상 완료로 판정할 수 없음.
- 코드 확인 지점: `changeSelectedTrackInstrument` → `configureTrackInstrument` → `configureSynth` / `configureDrumSynth`, `ensureInstrument`, 재생 컨텍스트 갱신 경로.
- 조사 항목: 프리셋 XML 속성과 FourOsc 파라미터 대응, 기존 상태 초기화, 런타임 파라미터 반영, 오디오 재생 컨텍스트 반영, 저장·복원. 원인은 아직 확정하지 않음.

재현·검증 절차:

1. 실행 파일과 창 제목의 버전을 기록하고 새 프로젝트를 만든다.
2. Generated Keys 트랙 하나를 추가해 Octave 4의 C4를 같은 길이로 연주한다.
3. 짧은 패턴을 녹음하고 재생해 변경 전 소리를 확인한다.
4. 정지 상태에서 8-Bit Lead로 변경한다. 직접 연주와 기존 패턴 재생을 각각 확인한다.
5. Cosmic Pad로 변경해 어택·릴리스 차이를 확인한 뒤 Generated Keys로 되돌린다.
6. 재생 중 변경, 음을 누른 상태의 변경, 다른 트랙을 둔 상태에서 반복한다.
7. 저장 후 앱을 재실행하고 불러와 같은 결과인지 확인한다.
8. 드럼끼리 변경과 Synth ↔ Drum 전환은 별도로 INST-AC02/03 기준으로 검증한다.

기록 항목: 빌드 버전, 오디오 장치, 이전/새 악기, 재생·녹음 상태, 입력 창, 직접 연주 결과, MIDI 재생 결과, 재실행 후 결과. 표시만 바뀌고 음색이 같으면 실패로 기록한다.

### BUG-002: 전체 자체 테스트 접근 위반 종료

- 상태: v0.1014와 v0.1015에서 실행 확인, 미해결.
- `--self-test` 종료 코드: `-1073741819`(Windows 접근 위반, `0xC0000005`). 정확한 충돌 지점과 BUG-001 관련성은 미확인.
- 프로젝트 왕복 저장과 렌더 기반 음색 테스트 코드가 존재하지만, 전체 테스트가 정상 완료되지 않아 이 경로들의 통과를 주장할 수 없음.
- 음색 테스트는 일부 프리셋의 렌더 결과 차이를 검사한다. 실제 UI에서 재생 중 악기를 변경하는 시나리오 전체를 보장하지 않음.

### UX-001: 창에 따라 Z/X 의미가 다름

- 건반 창: 옥타브 변경. 메인 창: Kick/Snare.
- 현재 동작을 명시한 것이며, 단축키 통일이나 별도 드럼 패드 창은 후속 결정 사항이다.

### 진단 추가: 신시사이저 비교 음원

`--render-synth-demos`는 현재 앱의 다섯 Synth 프리셋을 수정 없이 각각 새 FourOsc 인스턴스에 적용해 같은 멜로디로 처리한다. 120 BPM, MIDI 벨로시티 100, 8초 연주와 4초 잔향을 포함한 12초 스테레오 WAV를 `build/synth-demos/`에 생성한다. 양자화 전 모든 음원에 동일한 0.25 배율을 적용하며 개별 음량 정규화는 하지 않는다. 앱 UI와 별개인 진단 명령이며 기본 앱의 프리셋·음량 동작을 변경하지 않는다.

`python tools/compare-synth-demos.py`는 NumPy로 무음·클리핑과 파형 동일 여부를 확인하고, 순차 비교 파일 및 `comparison.json`을 만든다. 이 진단은 FourOsc를 직접 오프라인 처리하므로, 기존 전체 자체 테스트의 Edit 렌더 경로나 실행 중 악기 교체 검증을 대신하지 않는다. 각각 생성한 프리셋의 출력이 다르더라도 BUG-001이 해결된 것으로 판정하지 않는다.

v0.1035는 확대된 타임라인에서 보이는 시간 범위 밖의 노트, 루프 및 재생 헤드를 트랙 콘텐츠 경계로 제한한다. 음계·악기 라벨 영역에서 화면 밖 노트를 선택하거나 재생 헤드를 이동하지 않는다.

v0.1036은 PLAY와 STOP을 한 버튼으로 통합하고 Space를 기본 Play/Stop 단축키로 변경한다. Loop 단축키는 기본 미지정이며 `Edit > Shortcuts...`에서 Play/Stop과 함께 설정한다. 기존 단축키 스키마의 Kick 보조키는 제거하고 사용자 프로필은 새 스키마로 자동 변환한다.

## 7. 미구현·후속 범위

다음 기능은 제품 방향에 포함되지만 현재 완료 기능으로 취급하지 않는다.

| 영역 | 후속 기능 |
| --- | --- |
| 타임라인 | 확대·축소, 스크롤, 템포·그리드 스냅 UI, 16초 이상 작업 범위 확장 |
| 입력 | 별도 드럼 패드 창, 외부 MIDI 입력 UI, 벨로시티·키 재지정 |
| 편집 | 사용자용 Undo/Redo 조작, 복사·붙여넣기 등 편집 확장 |

| 파일 | 오디오 가져오기, 음원 라이선스 메타데이터, 사용자용 WAV 출력 |
