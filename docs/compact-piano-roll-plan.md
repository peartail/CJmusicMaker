# 12행 피아노 롤과 옥타브 구분 계획

기준 버전: v0.1027
상태: 구현 완료, 검증 결과는 기능 명세 참고

## 문제와 목표

현재 신시사이저 트랙은 건반 창의 3옥타브 음역을 그대로 사용해 타임라인에 36개 음높이 행을 만든다. 트랙 높이가 제한된 상태에서는 각 행과 노트가 너무 작아져 확인과 편집이 불편하다.

목표는 신시사이저 트랙의 타임라인을 C부터 B까지 12개 행으로 접고, 서로 다른 옥타브의 노트는 같은 음 이름 행 안에서 구분하는 것이다. 예를 들어 C3, C4, C5는 모두 `C` 행에 놓이지만 실제 음높이는 서로 다르게 유지한다.

이 표시는 **Pitch-class folded view(피치 클래스 접기 보기)**에 해당한다. 피치 클래스는 옥타브를 제외한 C, C#, D 같은 12가지 음 이름을 뜻한다.

## 핵심 결정

- 타임라인의 신시사이저 트랙만 기본 12행으로 표시한다.
- Tracktion의 MIDI 노트 번호는 그대로 보존한다. 화면만 접으며 프로젝트 데이터는 변환하지 않는다.
- 행은 `C, C#/Db, D, D#/Eb, E, F, F#/Gb, G, G#/Ab, A, A#/Bb, B` 순서로 고정한다.
- 각 노트 블록에 전체 음 이름을 표시한다. 예: `C3`, `C4`, `F#5`.
- 옥타브마다 구분색을 주되 숫자 표기를 항상 함께 사용한다. 색상을 구별하기 어려운 사용자도 숫자로 확인할 수 있어야 한다.
- 드럼 트랙은 현재의 1행 표시를 유지한다.
- 건반 창의 연주 범위와 단축키, 녹음 가능한 음역은 이번 변경에서 줄이지 않는다.

즉, `타임라인 표시 행 수`와 `연주 가능한 음역`을 분리한다. 다른 옥타브를 연주하기 위해 새 트랙을 만들 필요는 없다.

## 화면 설계

### 1. 행과 라벨

신시사이저 트랙 왼쪽에는 옥타브 숫자를 뺀 12개 음 이름만 한 번씩 표시한다. 검은 건반에 해당하는 행은 배경을 조금 어둡게 하여 흰 건반 행과 구분한다.

### 2. 노트 표시

노트 블록은 다음 정보를 함께 보여 준다.

- 채움색 또는 왼쪽 색 띠: 옥타브 구분
- 텍스트: 실제 음 이름과 옥타브 숫자(예: `A3`)
- 선택 테두리: 현재 선택된 노트

노트 폭이 좁아 전체 라벨을 넣을 수 없으면 옥타브 숫자만 표시한다. 선택하거나 마우스를 올렸을 때 상태 영역에는 전체 음 이름을 보여 준다.

옥타브 색은 프로젝트나 트랙에 따라 바뀌지 않는 고정 팔레트를 사용한다. 현재 입력 옥타브만 특별한 색으로 칠하면 옥타브를 변경할 때 이미 녹음된 노트의 의미가 바뀌어 보일 수 있으므로 피한다.

### 3. 같은 위치에 겹치는 노트

C3와 C4처럼 음 이름과 시간이 모두 겹치는 경우 한 노트가 완전히 가려지면 안 된다.

겹친 노트는 같은 행 안에서 음높이 순서대로 세로 공간을 나누어 표시한다. 클릭 판정도 나뉜 실제 영역을 먼저 사용하므로 C3와 C4를 각각 직접 선택할 수 있다. 현재 16초 프로토타입에서는 화면을 그릴 때 겹침을 계산하며, 긴 클립에서 성능 문제가 측정될 때만 배치 캐시를 추가한다.

이 동작은 12행 보기의 필수 안전장치다. 겹친 노트를 삭제하거나 이동할 때 다른 옥타브의 노트를 잘못 선택하면 안 된다.

## 편집 규칙

- 좌우 드래그: 현재처럼 시작 시간을 이동한다.
- 노트 오른쪽 손잡이 드래그: 현재처럼 길이를 변경한다.
- 위아래 드래그: 옥타브는 유지하고 C~B 음 이름만 변경한다.
- 선택 노트의 옥타브 변경: 별도의 `Octave -` / `Octave +` 명령으로 MIDI 음높이를 12씩 변경한다.
- 옥타브 변경 결과는 MIDI 0~127 범위 안으로 제한한다.
- 삭제, 저장, 불러오기, 재생 결과는 현재와 같아야 한다.

별도 옥타브 명령은 노트 컨텍스트 메뉴에 먼저 넣는 것이 가장 단순하고 발견하기 쉽다. 전용 버튼이나 추가 단축키는 실제 사용 후 필요성이 확인될 때 추가한다.

## 데이터와 계산

화면 계산만 다음과 같이 바꾼다.

```text
lane        = midiPitch % 12
octave      = midiPitch / 12 - 1
displayName = noteName[lane] + octave
```

예를 들어 MIDI 48(C3), 60(C4), 72(C5)는 모두 0번 `C` 행에 표시되지만 Tracktion `MidiNote`의 노트 번호는 각각 48, 60, 72로 유지한다.

별도의 복제된 노트 모델은 만들지 않는다. Tracktion `Edit`와 `MidiNote`가 계속 원본 데이터이며, UI는 그 값을 화면 좌표와 라벨로 변환만 한다.

## 코드 변경 범위

구현 시 `src/Main.cpp`의 다음 책임을 분리해 수정한다.

1. `timelineLaneCount`: 신시사이저는 노트 음역과 관계없이 12를 반환한다.
2. `laneForPitch`: 신시사이저 노트를 MIDI 번호가 아닌 `% 12` 행에 배치한다.
3. `pitchForY`: 세로 드래그 시 선택 노트의 옥타브를 유지한 채 목표 행의 음 이름으로 바꾼다.
4. `drawTimeline`: 행 라벨, 옥타브 색, 노트의 숫자 라벨과 겹침 표시를 그린다.
5. `findTimelineNote`: 같은 위치에 겹친 노트의 분할 영역을 우선해 선택한다.
6. 노트 컨텍스트 메뉴: 선택 노트를 한 옥타브 위/아래로 이동한다.

현재 `timelinePitchRange`는 36행 확장에 사용되고 있으므로, 구현 후에는 표시 행 계산에서 제거한다. 저장 데이터 검사나 다른 용도가 없다면 함수 자체도 삭제해 중복 개념을 남기지 않는다.

## 구현 순서

### 1단계: 12행 표시

- 신시사이저 트랙을 고정 12행으로 표시
- 기존 MIDI 노트를 음 이름 행으로 배치
- 노트에 옥타브 숫자와 고정 색상 표시
- 드럼 트랙 동작 유지

### 2단계: 안전한 편집

- 세로 드래그 시 기존 옥타브 유지
- 컨텍스트 메뉴의 `Octave -` / `Octave +`
- 겹친 노트 분할 표시와 개별 선택

### 3단계: 검사와 문서 갱신

- 전용 좌표/음높이 self-test 추가
- 저장·불러오기 전후 MIDI 노트 번호 동일성 검사
- 기존 노트 편집, 단축키, 옥타브, 프로젝트 self-test 재실행
- `README.md`와 `docs/functional-spec.md`를 구현 결과에 맞게 갱신
- 사용자 테스트 가능한 빌드이므로 구현 시 `VERSION`을 0.0001 증가

## 자동 검사 항목

- MIDI 48, 60, 72가 모두 C 행으로 계산되는가.
- 세 노트의 표시 라벨이 각각 C3, C4, C5인가.
- D 행으로 세로 이동한 C4가 D4가 되고 D3 또는 D5로 바뀌지 않는가.
- `Octave +`를 실행한 D4가 D5가 되는가.
- MIDI 범위 밖으로 옥타브 이동이 차단되는가.
- 같은 시간의 C3, C4를 각각 선택하고 편집할 수 있는가.
- 저장·불러오기 전후 MIDI 번호, 시작 시간, 길이가 바뀌지 않는가.
- 드럼 트랙은 계속 한 행이며 기존 편집이 동작하는가.

## 완료 조건

- 기본 높이의 신시사이저 트랙에서 12개 행과 노트를 읽을 수 있다.
- 서로 다른 옥타브가 숫자만으로도 명확히 구분된다.
- 12행으로 접어도 재생되는 음높이와 저장된 MIDI 데이터가 바뀌지 않는다.
- 같은 음 이름의 여러 옥타브가 겹쳐도 각 노트를 선택·이동·삭제할 수 있다.
- 별도 트랙을 만들지 않고 한 신시사이저 트랙에서 여러 옥타브를 사용할 수 있다.

## 이번 계획에서 제외

- 건반 팝업 자체를 3옥타브에서 1옥타브로 축소하는 작업
- 36개 단축키 설정 형식을 12개로 마이그레이션하는 작업
- 자동으로 사용 중인 음만 남기는 Scale/Fold 필터
- 벨로시티, 코드 편집, 피아노 롤 확대/축소

이 항목들은 12행 타임라인을 먼저 실제로 사용해 본 뒤 필요할 때 별도 계획으로 다룬다.
