# MusicBitMaker 단축키 설정 기능 기획서

작성일: 2026-10-17 · 상태: 구현 전 초안 · 기준 앱 버전: v0.1019 · 대상: Windows x64 네이티브 앱

## 1. 목적과 범위

사용자가 화면 건반과 드럼 패드를 보면서 연주 단축키를 확인하고 바꿀 수 있게 한다. 설정 진입점은 **`Edit > Shortcuts...`** 이다. 창에는 3옥타브 피아노, 네 가지 드럼 패드, 음역 이동 동작을 그림으로 표시한다. 그림의 각 대상에는 현재 지정된 단일 키를 직접 적는다.

첫 구현 범위는 피아노 연주, 드럼 연주, 건반 표시 음역 이동이다. 피아노의 36개 음은 각각 별도의 단일 키를 지정하거나 비워 둘 수 있다. Alt/Shift를 누른 상태로 다른 옥타브를 연주하는 기능은 포함하지 않는다. 프로젝트 저장·편집, 재생·녹음 같은 일반 명령의 키 재지정은 같은 화면에 나중에 추가할 수 있도록 구조만 고려한다. 마우스 연주와 기존 MIDI 노트 데이터는 단축키 변경의 영향을 받지 않는다.

## 2. 현재 구현과 바꿔야 할 지점

- 앱 메뉴는 `File`, `View`만 있다. 메인 창과 별도 건반 창이 각각 키 입력을 처리한다.
- 화면 건반은 3옥타브 36음을 그리지만 PC 키는 첫 13음에 `A W S E D F T G Y H U J K`로 고정돼 있다.
- 건반 창에서 `Z/X`는 음역 이동이고, 메인 창에서 `Z/X/C/V`는 드럼이다. 메인 창에서 Space도 Kick을 친다.
- 현재 `ApplicationProperties`는 앱 설정을, Tracktion `Edit`는 프로젝트의 음악 상태와 건반 시작 옥타브를 저장한다.
- 키를 누른 상태에서 단축키 설정, 화면 음역, 창 포커스, 악기 또는 트랙을 바꾸면 원래 음에 정확히 Note Off가 전달되어야 한다.

관련 구현 위치: `src/Main.cpp`의 `MainComponent` 메뉴·키 입력, `KeyboardPadComponent` 입력·그리기, `triggerDrum`, `updateCombinedLiveNote`, `releaseAllLiveNotes`.

## 3. 제안하는 기본 배치

가운데 옥타브의 흰 건반은 요청대로 `A S D F G H J`다. 검은 건반은 기존의 `W E T Y U`를 사용한다. 왼쪽·오른쪽 옥타브는 처음에는 **미지정**이며, 설정 창에서 각 음에 원하는 단일 키를 직접 배정한다. `N`은 화면 음역을 한 옥타브 내리고 `M`은 올린다. `K`는 기본 연주 배치에서 제외한다.

| 음 | C | C♯ | D | D♯ | E | F | F♯ | G | G♯ | A | A♯ | B |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 가운데 | A | W | S | E | D | F | T | G | Y | H | U | J |
| 왼쪽 | 미지정 | 미지정 | 미지정 | 미지정 | 미지정 | 미지정 | 미지정 | 미지정 | 미지정 | 미지정 | 미지정 | 미지정 |
| 오른쪽 | 미지정 | 미지정 | 미지정 | 미지정 | 미지정 | 미지정 | 미지정 | 미지정 | 미지정 | 미지정 | 미지정 | 미지정 |

| 동작 | 제안 기본값 | 현재 동작과의 관계 |
| --- | --- | --- |
| 화면 음역 내림 / 올림 | N / M | 건반 창의 Z/X를 대체 |
| Kick | Z, 추가 키 Space | 현재 메인 창 입력 유지 |
| Snare | X | 현재 메인 창 입력 유지 |
| Closed Hat / Open Hat | C / V | 현재 메인 창 입력 유지 |

**기본 음높이 제안:** 새 프로젝트의 화면을 C3~B5로 놓으면 가운데 옥타브가 C4~B4가 된다. 현재 기본 화면은 C4~B6이므로 가운데가 C5~B5다. 기존 프로젝트는 저장된 시작 옥타브를 유지하고, 새 프로젝트의 시작값을 3으로 바꾸는 안을 권장한다. 이 값은 구현 전에 확정할 결정 사항이다.

## 4. 설정 화면

메뉴에서 `Shortcuts...`를 열면 별도 설정 창이 뜬다. 창은 다른 연주 입력을 가로채지 않도록 **설정 모드**가 된다. 설정 창이 활성화된 동안 누른 키는 소리를 내지 않고 새 바인딩 후보로만 처리한다.

현재 건반 창은 항상 위에 표시되므로 설정 창을 열 때 누른 음을 종료하고 설정 창을 그보다 앞에 놓는다. 설정 창을 닫으면 기존 건반 창의 표시와 포커스를 복구한다.

```text
Edit > Shortcuts...
┌─────────────────────────────────────────────────────────────┐
│ [Piano]  [Drums]  [Controls]                                │
│                                                             │
│  왼쪽 음역        가운데 음역          오른쪽 음역           │
│  ┌────────── 3옥타브 피아노 그림 · 각 음에 키 표시 ──────┐ │
│  │ C3 ... B3  │  C4 ... B4  │  C5 ... B5              │ │
│  └───────────────────────────────────────────────────────┘ │
│  선택: 가운데 C4   현재: A                                  │
│  [새 키 입력]  [해제]  [기본값 복원]                          │
│  충돌 또는 예약 키 안내                                     │
│                                          [취소] [적용]       │
└─────────────────────────────────────────────────────────────┘
```

- **Piano:** 피아노 그림의 36개 음 중 하나를 클릭하면 음 이름과 현재 단축키를 보여 준다. 각 음의 키를 독립적으로 지정하거나 해제한다. 미지정 건반에는 `—`를 표시하며 마우스로는 계속 연주할 수 있다.
- **Drums:** Kick, Snare, Closed Hat, Open Hat을 2×2 패드로 그린다. 각 패드에 키를 표시하며 Kick의 추가 키 Space도 별도 슬롯으로 편집한다.
- **Controls:** 화면 음역 내림/올림의 현재 키를 표시하고 N/M을 다른 단일 키로 지정할 수 있게 한다.
- 외부 이미지 파일 대신 JUCE로 건반과 패드를 직접 그려 창 크기 변경과 DPI 배율에서도 선명하게 표시한다. 현재 건반의 음계 색상은 유지하고, 선택된 음과 설정 중인 대상은 별도 테두리로 구분한다.
- 키 할당은 그림의 대상을 선택 → `새 키 입력` → 단일 키 누르기 → 충돌 확인 → `적용` 순서다. `Esc`는 입력 대기만 취소한다. `취소`는 창에서 바꾼 전체 내용을 버리고, `기본값 복원`은 적용 전 미리보기만 바꾼다.

## 5. 입력 및 충돌 규칙

1. 피아노 키는 **건반 창에 포커스가 있을 때** 우선 연주한다. 메인 창에서도 같은 배치를 사용할 수 있게 연결하되, 메뉴·대화상자·텍스트 편집·단축키 설정 창에 포커스가 있을 때는 연주하지 않는다. 드럼은 메인 창에서 기존처럼 연주한다.
2. 한 단일 키가 피아노 음, 드럼 타격, 음역 이동 중 둘 이상에 배정되면 충돌을 표시하고 `기존 할당 대체` 또는 `취소`를 선택하게 한다. 피아노와 드럼이 서로 다른 창에 있어도 동일 키 중복은 허용하지 않아 창을 바꿔도 의미가 분명하다.
3. 연주 단축키에는 보조키 조합을 사용하지 않는다. Ctrl/Alt/Shift, Windows 키, Escape, Delete/Backspace 같은 시스템·편집 키는 단일 연주 키로 지정할 수 없다. 기존 `Ctrl+N/O/S`, `Ctrl+Shift+S` 등 앱 명령은 그대로 동작한다.
4. Windows 한글/영문 입력 상태와 키보드 반복 입력에서 같은 물리 키가 같은 음을 가리키는지 확인한다. 키보드 배열에 따라 사용할 수 없는 키는 설정 창에서 명확히 안내한다.
5. 누른 키가 가리킨 **실제 MIDI 음높이와 입력 출처**를 키 해제 때까지 기억한다. 화면 음역 변경, 설정 적용, 포커스 이탈, 창 닫기, 트랙·악기 변경 시 기존 음을 먼저 종료한다. 이미 녹음된 MIDI 노트의 음높이는 바꾸지 않는다.
6. 드럼 키를 길게 누르거나 OS 반복 이벤트가 와도 의도하지 않은 연속 트리거가 일어나지 않도록 한 번의 키 누름을 한 번의 타격으로 취급한다.

## 6. 설정 데이터와 코드 구조

- 권장안은 단축키를 프로젝트의 음악 데이터가 아니라 **사용자 앱 설정**으로 저장하는 것이다. 모든 프로젝트에 같은 배치가 적용되며, `.tracktionedit` 파일에는 기록하지 않는다. 기존 `juce::ApplicationProperties`를 사용한다.
- 설정에는 `schemaVersion`, 피아노 36개 음의 키 또는 미지정 상태, 4개 드럼 키와 Kick 추가 키, 음역 이동 키를 둔다. 값이 없거나 손상됐으면 기본 배치를 적용한다. `적용` 시 검증과 저장을 마친 뒤 두 입력 창과 표시 라벨을 동시에 갱신한다.
- 단일 키 해석을 한 곳의 `ShortcutMap`/입력 디스패처로 모으고 `MainComponent`, `KeyboardPadComponent`, 설정 창은 이를 사용한다. 건반·드럼 음원 및 녹음 상태는 계속 Tracktion Edit가 담당한다.
- 저장 형식은 표시 문자보다 키 코드를 기준으로 한다. JUCE 입력이 한글 IME 상태에서 다른 코드로 들어오는 경우 Windows 키 식별 방식을 별도로 확인한다.
- 파일 저장, 설정 UI, 로그 작성은 JUCE 메시지 스레드에서만 한다. 실시간 오디오 콜백에는 단축키 처리나 파일 입출력을 넣지 않는다.
- 사용자 설정 형식에는 버전을 두어 이후 키 재지정 범위가 늘어도 옛 설정을 읽을 수 있게 한다. 설정 창의 단축키 표시는 실제 디스패처와 같은 데이터를 사용한다.

## 7. 구현 순서

1. 현재 고정 키 목록을 정리하고, Windows에서 단일 키·한글 IME 입력을 작은 진단으로 확인한다.
2. 기본값·중복 검사·저장·로드를 갖춘 단축키 모델과 피아노/드럼/음역 이동 디스패처를 만든다.
3. 메인 창과 건반 창의 하드코딩 키 처리를 공통 디스패처로 바꾸고, Note Off 및 포커스 전환 처리를 정리한다.
4. `Edit > Shortcuts...` 창과 피아노·드럼 그림, 키 입력 캡처, 충돌 안내, 적용/취소/기본값 복원을 추가한다.
5. 실제 건반 창·드럼 버튼에 현재 단축키를 표시하고, 사용자 설명과 기능 명세를 갱신한다. 사용자 테스트용 빌드에서 `VERSION`을 0.0001 올린다.

## 8. 완료 기준

| ID | 확인할 동작 |
| --- | --- |
| SC-01 | `Edit > Shortcuts...`에서 3옥타브 건반, 드럼 네 패드, 음역 이동과 현재 키가 보인다. |
| SC-02 | 기본 배치에서 A~J가 가운데 옥타브의 흰 건반, W/E/T/Y/U가 검은 건반을 연주한다. 왼쪽·오른쪽은 미지정 상태로 시작하며 각 음에 서로 다른 단일 키를 지정할 수 있다. |
| SC-03 | N/M으로 화면 음역이 내려가고 올라간다. 건반 창의 Z/X는 음역 이동을 하지 않는다. |
| SC-04 | 피아노 36개 음의 키 지정·해제, 드럼 키, 음역 이동 키를 바꾸고 적용하면 연주·녹음·표시가 즉시 일치한다. 앱 재시작 후에도 유지된다. |
| SC-05 | 단일 키 충돌과 예약 키를 지정할 수 없고 이유가 표시된다. 취소는 기존 설정을 유지한다. |
| SC-06 | 마우스 연주와 기존 MIDI 재생은 그대로 동작한다. 설정·포커스·음역·악기 전환 후 남는 음이 없다. |
| SC-07 | 드럼 Z/X/C/V 및 Kick Space가 기본값으로 작동한다. 사용자 지정 후에도 키 반복으로 불필요한 연타가 없다. |
| SC-08 | 실제 Windows에서 지정한 왼쪽·가운데·오른쪽 음역의 단일 키, 한글/영문 입력, 건반·메인 창 포커스 전환을 확인한다. |

자동 검사는 36음 매핑/충돌/설정 왕복과 Note On/Off 전환에 집중한다. 실제 Windows 앱에서는 세 옥타브에 지정한 키를 직접 연주하고 드럼 및 녹음 결과를 확인한다. 표준 빌드와 `--self-test-keyboard-octave`, 전체 `--self-test`도 다시 실행한다.

## 9. 구현 전 확정할 항목

1. **새 프로젝트 기본 음역:** 가운데를 C4~B4로 두기 위해 화면 시작을 C3으로 바꿀지, 현재 C4 시작을 유지해 가운데 C5~B5로 둘지. 권장안은 새 프로젝트만 C3 시작이다.
2. **메인 창의 연주 범위:** 메인 창에서도 건반 창과 동일한 36음 단일 키 배치를 사용할지. 권장안은 동일한 배치를 사용하고 피아노·드럼·음역 이동의 키 충돌을 전체 앱에서 막는 것이다.
3. **왼쪽·오른쪽 기본값:** 두 옥타브를 미지정으로 시작하고 사용자가 필요한 음만 배정할지. 권장안은 미지정이다. 정해 두지 않은 키가 다른 앱 명령이나 드럼 입력과 충돌하지 않는다.
4. **일반 명령 확장:** 첫 버전에서는 피아노·드럼·음역 이동까지만 편집하고, Play/Stop/Record와 파일 명령은 다음 단계로 둔다.
5. **설정 적용 범위:** 단축키를 모든 프로젝트에 공통인 사용자 설정으로 둘지, 프로젝트마다 다르게 둘지. 권장안은 사용자 설정이다. 프로젝트별 음악 데이터와 구분하기 쉽고 새 프로젝트를 열어도 손에 익은 배치를 유지한다.

이 문서는 구현안이다. 현재 앱의 키 배치와 메뉴는 아직 바뀌지 않았다.
